Comparator & Sorting

A concise, practical revision sheet for arrays, intervals, greedy problems, heaps, and frequency-based questions.

Most-used pattern: 
Arrays.sort(arr, (a, b) -> Integer.compare(a[0], b[0]));
Use this when arr is an object array such as int[][]. It sorts by column 0 in ascending order.

1. Comparator in 30 seconds

Comparator<T> tells Java how to order two objects. Its key method is:

int compare(T a, T b);
ResultMeaning
Negativea should come before b
ZeroThey are equal for this sorting rule
Positivea should come after b
Remember: For ascending numeric order, compare a with b. For descending order, reverse the arguments.

2. The essential sorting templates

Integers and lists

// Primitive array: ascending
int[] nums = {5, 2, 8, 1};
Arrays.sort(nums);

// Integer[]: descending (Comparator works on objects)
Integer[] boxed = {5, 2, 8, 1};
Arrays.sort(boxed, (a, b) -> Integer.compare(b, a));

// List: ascending / descending
list.sort(Comparator.naturalOrder());
list.sort(Comparator.reverseOrder());

2D arrays

// Sort by column 0, ascending
Arrays.sort(arr, (a, b) -> Integer.compare(a[0], b[0]));

// Sort by column 0, descending
Arrays.sort(arr, (a, b) -> Integer.compare(b[0], a[0]));

// Sort by column 1, ascending
Arrays.sort(arr, (a, b) -> Integer.compare(a[1], b[1]));

// Sort by column 1, descending
Arrays.sort(arr, (a, b) -> Integer.compare(b[1], a[1]));

Multiple conditions / tie-breaker

// First: column 0 ascending
// If tied: column 1 ascending
Arrays.sort(arr, (a, b) -> {
    int first = Integer.compare(a[0], b[0]);
    if (first != 0) return first;
    return Integer.compare(a[1], b[1]);
});

// Shorter equivalent using Comparator methods
Arrays.sort(arr,
    Comparator.comparingInt((int[] a) -> a[0])
              .thenComparingInt(a -> a[1]));

3. Strings and custom objects

String[] words = {"banana", "apple", "cat"};

// Alphabetical
Arrays.sort(words);

// Reverse alphabetical
Arrays.sort(words, (a, b) -> b.compareTo(a));

// Shorter words first
Arrays.sort(words,
    (a, b) -> Integer.compare(a.length(), b.length()));

For objects, compare the property you need:

class Employee {
    String name;
    int salary;
}

// Salary ascending
employees.sort((a, b) -> Integer.compare(a.salary, b.salary));

// Salary descending
employees.sort((a, b) -> Integer.compare(b.salary, a.salary));

// Name alphabetical
employees.sort((a, b) -> a.name.compareTo(b.name));

// Salary descending, then name alphabetical
employees.sort(
    Comparator.comparingInt((Employee e) -> e.salary)
              .reversed()
              .thenComparing(e -> e.name)
);

4. PriorityQueue: Min Heap vs Max Heap

Min Heap

Smallest element at the head.

PriorityQueue<Integer> pq =
    new PriorityQueue<>();
Max Heap

Largest element at the head.

PriorityQueue<Integer> pq =
    new PriorityQueue<>(
        (a, b) -> Integer.compare(b, a)
    );

PriorityQueue of pairs / int arrays

// Min heap based on second value
PriorityQueue<int[]> pq = new PriorityQueue<>(
    (a, b) -> Integer.compare(a[1], b[1])
);

// Max heap based on second value
PriorityQueue<int[]> maxPq = new PriorityQueue<>(
    (a, b) -> Integer.compare(b[1], a[1])
);

Useful for: Kth largest/smallest, Top K frequent, K closest points, task scheduling, and merging sorted lists.

PriorityQueue reminder: peek() reads the head; poll() removes and returns it. The head is determined by the comparator—not insertion order.

5. Sorting a HashMap by values

A HashMap itself is not sorted by value. Copy its entries into a list, then sort the list.

Map<Integer, Integer> map = new HashMap<>();

List<Map.Entry<Integer, Integer>> entries =
    new ArrayList<>(map.entrySet());

// Value descending
entries.sort((a, b) ->
    Integer.compare(b.getValue(), a.getValue())
);

// Tie-break by key ascending
entries.sort(
    Map.Entry.<Integer, Integer>comparingByValue(
        Comparator.reverseOrder())
        .thenComparing(Map.Entry.comparingByKey())
);

6. Comparable vs Comparator

ComparableComparator
compareTo()compare()
Defines a class's natural orderingDefines an external/custom ordering
Implemented by the class being sortedCan be created separately, often with a lambda
Usually one natural orderMultiple sorting strategies are easy
// Comparable example
class Student implements Comparable<Student> {
    int marks;

    public int compareTo(Student other) {
        return Integer.compare(this.marks, other.marks);
    }
}

// Comparator example
Comparator<Student> byMarksDescending =
    (a, b) -> Integer.compare(b.marks, a.marks);

7. Common mistakes to avoid

  • Don't use subtraction: a - b can overflow. Prefer Integer.compare(a, b).
  • Primitive array limitation: Arrays.sort(int[]) does not accept a Comparator. Use Integer[] or a custom approach if custom ordering is required.
  • Comparator contract: comparisons should be consistent and transitive. Avoid inconsistent rules.
  • Equal keys: return 0 when the compared fields are equal; add thenComparing if a tie-breaker is needed.
  • PriorityQueue: iterating over it does not produce fully sorted order. Repeatedly use poll() to retrieve elements in priority order.
