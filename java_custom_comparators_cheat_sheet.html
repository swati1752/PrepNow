Simple Field Sorting

Best for sorting by a single primitive key or object property

Primitive Primitive-Safe & Null-Clean

When sorting by a single field (such as an array index or getter), use static factory methods like Comparator.comparingInt(), comparingLong(), or comparing().

Key Benefits
  • Zero Auto-Boxing: `comparingInt` prevents creating unnecessary `Integer` objects during comparisons.
  • High Readability: Expresses intent cleanly without boilerplate comparator classes.
SimpleFieldSort.java 
import java.util.Arrays;
import java.util.Comparator;

public class SimpleSortDemo {
    public static void main(String[] args) {
        // 2D Interval Array: [[start, end]]
        int[][] meetings = {{5, 6}, {1, 3}, {8, 10}};

        // ✅ BEST: Sort by start time (index 0) ascending
        Arrays.sort(meetings, Comparator.comparingInt(a -> a[0]));

        // Output: [[1, 3], [5, 6], [8, 10]]
    }
}
2

Multi-Field Chaining

Best for secondary and tertiary tie-breaker rules

Chained Comparators

Chain .thenComparing() or specialized primitive variants like .thenComparingInt() onto a primary comparator to break ties gracefully.

Common Scenario

In scheduling or interval problems, you often sort intervals primarily by start time ascending, and secondarily by end time descending (or vice versa).

MultiFieldSort.java 
import java.util.Arrays;
import java.util.Comparator;

public class MultiSortDemo {
    public static void main(String[] args) {
        int[][] meetings = {{1, 5}, {1, 8}, {1, 3}, {2, 4}};

        // Primary: start time ASC
        // Secondary: end time DESC (using negative value or reversed order)
        Arrays.sort(meetings, Comparator
            .<int[]>comparingInt(a -> a[0])
            .thenComparingInt(a -> -a[1])
        );

        // Output: [[1, 8], [1, 5], [1, 3], [2, 4]]
    }
}

Complex Conditional Logic & Overflow Safety

Custom Lambdas using Integer.compare() instead of subtraction

⚠️ Overflow Pitfall

When write custom multi-branch comparisons inside lambda blocks, NEVER subtract numbers like (a - b)!

Why (a - b) breaks in Java:

If a = Integer.MIN_VALUE (-2,147,483,648) and b = 1, then a - b yields +2,147,483,647 due to integer underflow/overflow. This causes the sorting algorithm to return wrong results or crash.

✅ Fix: Always use Integer.compare(a, b).
SafeComplexSort.java 
import java.util.Arrays;

public class ComplexSortDemo {
    public static void main(String[] args) {
        int[][] data = {{1, 10}, {2, 5}, {1, 20}};

        // Custom Lambda block with Integer.compare()
        Arrays.sort(data, (a, b) -> {
            int firstCompare = Integer.compare(a[0], b[0]);
            if (firstCompare != 0) {
                return firstCompare; // Primary decision
            }
            // Secondary decision on tie: descending order for index 1
            return Integer.compare(b[1], a[1]);
        });
    }
}

Custom Classes: implementing Comparable<T>

Defining the natural default order for domain entities

Natural Ordering

For domain objects like a Meeting, implementing Comparable<Meeting> provides a standard order without needing to pass explicit comparators to Collections.sort() or Arrays.sort().

Comparable vs Comparator
  • Comparable: Defines single natural order inside the target class.
  • Comparator: Defines multiple custom ad-hoc orders outside the class.
MeetingEntity.java 
import java.util.Collections;
import java.util.List;

// Implementing Comparable<T> defines natural ordering
class Meeting implements Comparable<Meeting> {
    int start;
    int end;

    public Meeting(int start, int end) {
        this.start = start;
        this.end = end;
    }

    @Override
    public int compareTo(Meeting other) {
        // Natural Order: Sort by start time ascending
        return Integer.compare(this.start, other.start);
    }
}

public class ComparableDemo {
    public static void main(List<Meeting> meetings) {
        // Automatic sort using Meeting's compareTo()
        Collections.sort(meetings);
    }
}

Sorting Normal 1D Arrays (Primitives vs Objects)

Handling primitive arrays (int[]) vs wrapper/object arrays (Integer[])

Primitive Constraint Rule
Object Arrays (Integer[], String[])

Object arrays support generic type parameters. Therefore, Arrays.sort(T[], Comparator<? super T>) works seamlessly with lambdas or built-in comparators like Comparator.reverseOrder().

Integer[] nums = {5, 2, 8, 1};
Arrays.sort(nums, Comparator.reverseOrder());
Primitive Arrays (int[], double[])

Primitives cannot use custom comparators directly (throws compile error). You must either sort natively ascending, box them via Stream API, or reverse in-place.

int[] arr = {5, 2, 8, 1};
// Arrays.sort(arr, comp); ❌ Compile Error
Arrays.sort(arr); // ✅ Dual-Pivot Quicksort (Ascending)
PrimitiveArraySortingWorkarounds.java 
import java.util.Arrays;
import java.util.Comparator;

public class NormalArraySortDemo {
    public static void main(String[] args) {
        int[] primitiveArray = {5, 2, 8, 1, 9};

        // WORKAROUND 1: Box to Integer[] using Stream API for custom ordering
        Integer[] boxed = Arrays.stream(primitiveArray)
                                .boxed()
                                .toArray(Integer[]::new);

        Arrays.sort(boxed, (a, b) -> Integer.compare(b, a)); // Descending

        // WORKAROUND 2: Native In-Place Reverse (Zero heap allocations)
        Arrays.sort(primitiveArray); // Sorts ascending natively
        reverse(primitiveArray);      // Two-pointer swap for descending
    }

    private static void reverse(int[] arr) {
        for (int i = 0, j = arr.length - 1; i < j; i++, j--) {
            int temp = arr[i]; arr[i] = arr[j]; arr[j] = temp;
        }
    }
}
